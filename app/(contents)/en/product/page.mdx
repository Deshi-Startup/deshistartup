# Product: Turn a Customer Task into Something Usable

> **In short:** Define the task a customer needs to complete, then test the smallest useful version of that experience. Building more features is not evidence that the task works.

## Choose what needs testing

| Uncertainty | Useful next step |
|---|---|
| Is this a real problem? | [Customer interviews](/en/validation/customer-interviews) |
| Will anyone take a meaningful next step? | [Test demand](/en/journeys/test-demand) |
| What could a first version look like? | [MVP examples](/en/validation/mvp-examples) |
| How should we define the experiment? | [MVP experiment planner](/en/validation/mvp-experiment-planner) |

A sketch, manual service or demonstration may answer a question before you build a full product. State honestly what works and what is simulated; do not promise capabilities you cannot deliver.

## Write a one-task product brief

Describe **who / starting situation / task / successful outcome / likely failure / how you will observe it**. Add the device, connection, language and accessibility needs you must investigate with the intended users.

Ask someone from that group to try the task. Observe where they hesitate, need help or fail. Record what happened separately from your proposed solution. Fix the most important obstacle and try again.

Before handling real payments or sensitive information, identify the necessary permissions, data practices and safeguards. Start with the [legal roadmap](/en/legal-roadmap) for questions to resolve.
